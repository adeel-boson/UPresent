# Self-serve org signup, gated by super-admin approval, provisioned synchronously

New `Organization` signup is self-serve (anyone can request an org), but requests sit in a pending state until a `super-admin` approves them — chosen over fully-automatic activation because the product is pre-launch and unfunded with no other abuse controls in place yet. On approval, the tenant's Postgres schema ([ADR-0001](./0001-multi-tenant-schema-per-tenant-isolation.md)) is provisioned **synchronously**, not via a background job/queue — acceptable because provisioning one schema is fast and pilot-scale signup volume won't create contention. If signup volume or provisioning time grows, this will need to move to an async job with a "setting up" org state; that's a deliberate near-term limitation, not an oversight.
